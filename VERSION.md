## Release Checklist

When creating a new release:

1. **Update version in `src/version.cpp.in`:**

   ```cpp
   #define DEF_MONERO_VERSION "X.Y.Z"
   #define DEF_MONERO_RELEASE_NAME "Release Name"
   ```

2. **Update gitian build docs:**

   - `contrib/gitian/README.md`: Change `VERSION=vX.Y.Z`
   - `contrib/gitian/DOCKRUN.md`: Change `VERSION=vX.Y.Z`

3. **Update this file** with the new current version

4. **Commit and tag:**

   ```bash
   git add -A
   git commit -m "Release vX.Y.Z - Release Name"
   git tag -a vX.Y.Z -m "BOK-coin vX.Y.Z - Release Name"
   ```

5. **Push to trigger CI build:**

   ```bash
   git push origin bok-mainnet
   git push origin vX.Y.Z
   ```

6. **Review and publish** the draft release on GitHub

## Version Format

BOK-coin uses semantic versioning: `MAJOR.MINOR.PATCH`

- **MAJOR**: Breaking changes to consensus, network protocol, or wallet format
- **MINOR**: New features, non-breaking changes
- **PATCH**: Bug fixes, security patches

## Build Tag vs Version

The build system may append additional info:

- `DEF_MONERO_VERSION_TAG`: Git tag/branch info (auto-generated by CMake)
- `DEF_MONERO_VERSION_FULL`: Combines version + tag (e.g., `0.1.1-release`)
